# Claude Telegram Bridge 0.14.15

- Claude Code's feedback draft box is now recognized. After Claude drafts feedback with its SendFeedback tool, Claude Code replaces the input line with a box that reads `Bug report drafted: <title>` and `1 to review · 2 to send · 0 to dismiss`. Before this release, the bridge did not know this screen: `/feedback` from the phone failed with "input line not found", and a plain message pasted while the box was shown had its first character read as the box's key, so a message starting with `2` sent the draft without review. The bridge now holds new Telegram messages while the box is shown and sends a card with Send, Review and Dismiss buttons. Send presses `2` and reports success only when the receipt screen appears or the draft file disappears; Review presses `1` and hands over to the existing review card; Dismiss presses `0` and keeps the draft. The Send button appears only when the box title matches exactly one queued draft file. `/feedback` from the phone and the Send button of the draft notice card do not paste anything while the box or the feedback dialog is open.
- Approval cards for Claude Code's safety-check prompts work again with the current countdown wording. Claude Code now writes `Claude Code will automatically block this request in N:NN, to avoid holding up an unattended session`; the bridge only knew the earlier `deny … to avoid blocking progress on` wording, so the ticking countdown stayed in the card signature and every button press was refused as "the screen changed". Both wordings are now removed from the signature, so Yes and No are accepted while the timer runs, and prompts with 60 seconds or less remaining are announced as a silent notice without buttons, as before.

Validation: public export with the internal-symbol audit and the module parity gate, private-data and token scans with two independent scanners, public tests, twine check, and an installed-wheel resource check from a neutral folder in an isolated environment. Source bundle, wheel and source distribution are included.

This release is published on GitHub and PyPI. It does not restart an installed bridge.
