# Claude Telegram Bridge 0.14.16

- Question cards that are still waiting for an answer are now pinned in the private chat. When Claude Code asks a question through its AskUserQuestion tool, including the approval cards the bridge builds from it, the bridge pins the card's original message without a notification, so the question stays reachable from the top of the chat while new progress messages keep arriving. The pin is removed when the question is answered in Claude Code, when the card is a day old, or when the bridge binds to another session. The bridge touches only the pins it made: it never unpins other messages and never uses the unpin-all call. A pin is bookkeeping only; it never answers a question and never grants a permission. The bridge sends at most one pin or unpin request per polling tick, retries a failed request at most three times with 60 seconds between tries, writes the pin ownership to its state file before it calls Telegram, and keeps that state across a restart, so a confirmed pin is not repeated and a pin whose confirmation was lost is still cleaned up.
- A single-choice question card is now built even when the question text has scrolled completely off the top of a small terminal. Before this release the bridge needed at least one visible fragment of the quoted question to match the screen against the question Claude Code recorded; when the terminal showed only the blank line above option 1 and the options themselves, no card was sent and the phone received only the "screen check needed" notice. The bridge now matches the visible option descriptions against the recorded ones instead, when every option is visible from option 1 and the descriptions agree over at least 32 characters. If that blank line is missing or any visible fragment differs from the record, the bridge still refuses to guess.
- Single-choice questions with option previews are read from a temporarily taller window when their header is clipped. In a short terminal the preview box, the notes hint and the conversation lines can push the checkbox header and the rule line off the screen; the parser then produced nothing and the phone got the "screen check needed" notice instead of a card. When the preview-only hint (`n to add notes`) is on the last line but no header line is visible, the bridge now enlarges the window briefly to read the whole question and restores the size afterwards, as it already did for clipped multiple-choice questions. Confirming the chosen option from the phone reads the screen the same way, so the signature check no longer fails with "the screen changed" on small windows.

Validation: public export with the internal-symbol audit and the module parity gate, private-data and token scans with two independent scanners compared against the previous public tree, public tests, release-notes lint, twine check, and an installed-wheel resource check from a neutral folder in an isolated environment. Source bundle, wheel and source distribution are included.

This release is published on GitHub and PyPI. It does not restart an installed bridge.
