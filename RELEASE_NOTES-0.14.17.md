# Claude Telegram Bridge 0.14.17

- The flow mirror works again in the public build. Turning on `CLB_FLOW_MIRROR=1` (or creating the flow-mirror flag file) made the bridge log `flow mirror send failed (non-fatal): name 'node_label_emoji' is not defined` on every tool step, and the work-flow card, the stop button on that card, the "terminal input" mirror and the node-result card never reached the phone. The export that produces this public tree had removed six helper names together with the private regions they lived in: `node_label_emoji`, `_label_for_emoji`, `subject_particle`, `alt3_narrative_enabled`, `relay_alert_bin` and `reap_inflight_mesh_send_children`. Each of them is defined again with a public-safe behaviour: a node token that is not the configured node gets no mapped label and the default robot emoji, so cards show the raw token as before; narrative directive cards stay off; the Korean subject particle helper is the same as in the private source; the shutdown handler no longer references a mesh cleanup that the public build does not have.
- `CLB_RELAY_ALERT_BIN` is read as an optional setting. It names an operator script the bridge may call to relay a final answer when Telegram egress fails; when the variable is unset the bridge looks for `~/.config/claude-telegram-bridge/relay-alert.sh` and skips the relay quietly when that file does not exist. Nothing is called unless you create the file or point the variable at a script.
- Message delivery, question cards, pins and the busy-inject path are unchanged. With the flow mirror left off, this release behaves exactly like 0.14.16.

Validation: public export with a new undefined-global gate (every public module is read through the symbol table and the export stops on the first global name that is referenced but not defined; 14 modules at 0), the internal-symbol audit and the module parity gate, private-data and token scans with two independent scanners compared against the previous public tree, public tests including new assertions for the six restored helpers, release-notes lint, twine check, and an installed-wheel resource check from a neutral folder in an isolated environment. Source bundle, wheel and source distribution are included.

This release is published on GitHub and PyPI. It does not restart an installed bridge; after `pipx upgrade claude-telegram-bridge`, restart the bridge yourself.
