# Claude Telegram Bridge 0.14.19

- One-command "like the author" setup. `claude-telegram-bridge setup --like-author`, and the interactive wizard's new first question `Use the author's setup (recommended)? [Y/n]` (default yes), make a fresh install behave like the maintainer's own bridge. The private config is written with `CLB_BUSY_INJECT=1`, `CLB_FLOW_MIRROR=1`, `CLB_ASKUSER_CARDS_ENABLED=1` and `CLB_SUGGESTED_LOOP=1` (an existing config is backed up first). All three hooks this repository ships are downloaded and registered in the Claude settings in one merge, without touching unrelated hook entries: SessionStart, PreToolUse for `AskUserQuestion`, and PreToolUse for the Telegram MCP reply tool. The tmux session is created and Claude started inside it even in non-interactive mode. A self-check runs at the end: it reports whether the setup message reached the phone, waits up to 60 seconds for one message from the phone and watches the queue for its injection and answer, then types one probe into the Claude session and waits up to 90 seconds for its mirrored card. The three results are printed and sent to the chat. Answering `n` keeps the previous behaviour exactly.
- `claude-tg`, also available as `claude-telegram-bridge attach`. It reads the tmux socket and session from `bridge.env`, starts the session with Claude when it is missing, and attaches this terminal to it. Another attached terminal is left alone; the command only notes that both share the pane size.
- `claude-telegram-bridge setup --dry-run` prints every file, switch, hook and session the wizard would write, without contacting Telegram or touching the disk.
- `doctor` warns when a Claude CLI process runs on a tty other than the bridge pane's tty, because such a session is not connected to the phone, and points to `claude-tg`.
- `uninstall` removes all three hook registrations, and the hook files with `--purge`.

Validation: unit coverage for the preset config lines, the single-merge hook registration (existing chain preserved, idempotent, one backup), the declined path, the interactive default, dry-run isolation, attach argument building, missing-session creation, the no-detach rule, the missing-CLI failure, the outside-session doctor warning, both self-check outcomes, uninstall cleanup, and the parser and console-script wiring; two mutation probes (a preset switch removed, the attach session hard-coded); the public export with its undefined-global gate, module parity check and vocabulary gate; private-data and token scans compared against the previous public tree; release-notes lint; twine check; and an installed-wheel check in an isolated environment that runs `claude-tg --help` and `setup --like-author --dry-run`. Source bundle, wheel and source distribution are included.

This release is published on GitHub and PyPI. It does not restart an installed bridge and does not change an existing config; after `pipx upgrade claude-telegram-bridge`, run `claude-telegram-bridge setup --like-author` on a machine that should adopt the preset.
