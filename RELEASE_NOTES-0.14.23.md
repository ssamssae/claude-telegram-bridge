# Claude Telegram Bridge 0.14.23

- After you answer a question card, the card lists every option with its number, name and description, and marks your choice with ✅. With several answers, each chosen option gets a mark; a typed answer gets none. When everything does not fit in one message, the bridge shortens the kept question text first and then the option descriptions.
- Question cards with option previews now reach your phone on narrow terminals where option names wrap and the number moves to the next line. When the screen still cannot be read, the bridge builds the card from the open question itself.
- On narrow terminals the captured screen can still hold an older, redrawn copy of a question above the current one. The bridge now takes the cursor from the lowest `❯` line, so tapping an answer on a preview question card selects and submits it. Before, two cursor lines made the cursor unknown and the tap was never submitted.
- When you send a chat message while a question card is open, the message waits until you answer the question. The bridge posts one note under the card to say so (once per card).
- On macOS the bridge now restarts itself after its installed code changes, for example after `pip install --upgrade`. When the new file has stayed the same for 120 seconds and nothing is in progress (no running turn, queued message, open question or approval card, or message still being sent), the bridge saves its state and exits with code 75. The launchd service that `claude-telegram-bridge setup` installs then starts the new code. This is off by default on Linux and Windows. To turn it off, set `CLB_SELF_RESTART_ON_DEPLOY=0` or create `~/.claude/state/bridge-self-restart.off`. Turn it off if you run the bridge in a terminal without that service, because nothing starts the bridge again after it exits.
- With Korean as the bridge language, terminal approval cards explain the request: who asks (the main session or a subagent, with the subagent's description), a Korean title, what the tool does, why Claude Code asks, and a warning for `rm`. The buttons and how they match the screen stay the same. When a subagent asked, the receipt says that the main terminal may not show the result.
- Agent-control status no longer reports Claude Code's dimmed next-step suggestion in the composer as a typed draft. Only a composer whose text is entirely dimmed counts as a suggestion. Any normal character, a paste placeholder, an unknown style code or a change between the two captures still counts as a draft, so your typing stays protected.
- Progress cards show more about each running subagent: its latest action, how many tools it has used, and how long ago it last moved. When a subagent writes a `진행 n/m` progress mark, the card adds a bar, a percentage and an estimated time left. Other fractions, such as test counts, are not read as progress. The card also shows how many received messages Claude Code has not read yet.

Validation: each change is covered by unit tests in the maintainer's bridge suite, including real-screen fixtures for narrow-terminal question cards and the dimmed composer suggestion; the full public test suite; and an install check of the built wheel.

This release is published on GitHub and PyPI. Upgrading changes no installed hook or service file and needs no new settings.
